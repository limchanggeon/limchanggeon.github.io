# 기업 온라인 정보 수집 기준

과제 6단계(기업 온라인 정보 크롤링)를 구현하면서 무엇을 수집하고 무엇을 수집하지 않는지 정한 기준입니다.
코드는 `scripts/crawl.py`에 있습니다.

## 수집하는 것

| 대상 | 범위 |
|---|---|
| 회사 공식 홈페이지 | DART 기업개황에 회사가 직접 등록한 주소(`hm_url`)만 |
| 페이지 | 첫 페이지 + 회사소개·사업분야·비전·인재상 페이지, 회사당 최대 3쪽 |
| 내용 | 페이지 제목, 메타 설명, 본문 텍스트 일부(페이지당 1,500자) |

회사가 스스로 공개하고, 공시에 자기 사이트로 등록한 자료라서 수집 목적(내 이력과 맞는지 판단)에 비해 부담이 가장 작다고 판단했습니다.

## 수집 방식

- **robots.txt 확인**: 페이지를 가져오기 전에 robots.txt를 읽고, 막힌 경로는 가져오지 않습니다. robots.txt를 확인할 수 없으면(접속 오류 등) 그 사이트는 건너뜁니다. 401·403이면 전부 막힌 것으로, 404면 규칙이 없는 것으로 봅니다.
- **수집 주체 표시**: 요청마다 `CGLPortfolioBot/1.0 (+https://limchanggeon.github.io; student portfolio project)`을 보냅니다.
- **요청 간격**: 같은 사이트에는 1초에 한 번만 요청합니다.
- **재수집 제한**: 결과를 7일 동안 `.cache/web/`에 저장하고, 그동안은 다시 가져오지 않습니다.
- **로그인·검색·게시판·파일 다운로드 경로는 따라가지 않습니다.**

## 수집한 내용의 사용

- Gemini 적합도 분석과 자기소개서 작성에 회사 정보의 근거로 넣습니다.
- 화면에는 홈페이지에서 확인한 사실 1~3줄과 **출처 주소, 수집 시각**만 보여 줍니다. 수집한 본문을 그대로 다시 싣지 않습니다.
- 수집한 본문은 웹페이지에서 가져온 자료로만 다루고, 그 안의 문장을 AI에게 주는 지시로 쓰지 않도록 프롬프트에 명시했습니다.
- 수집 원문(`.cache/web/`)은 저장소에 올리지 않습니다(`.gitignore`).

## 수집하지 않는 것과 이유

2026-10-14에 각 사이트의 robots.txt를 이 수집기 이름으로 직접 판정한 결과입니다.

| 사이트 | robots.txt 판정 | 수집 여부 | 이유 |
|---|---|---|---|
| 네이버 뉴스 | 차단 | 안 함 | robots.txt가 막음. 기사는 언론사 저작물 |
| 링크드인 | 차단 | 안 함 | robots.txt가 막음 |
| 원티드 | robots.txt 접근 403 | 안 함 | 규칙을 확인할 수 없음 |
| 사람인, 잡코리아 | 허용 | 안 함 | 채용공고 데이터베이스는 플랫폼이 만든 자료. robots.txt가 허용해도 이용약관 확인이 먼저 필요 |
| 잡플래닛, 블라인드 | 허용 | 안 함 | 이용자가 쓴 후기·게시글. 작성자 권리와 개인정보 문제가 있어 과제 범위에서 제외 |

robots.txt가 허용한다고 해서 수집해도 되는 것은 아니라는 점이 이번 판단의 핵심입니다.
robots.txt는 검색엔진 같은 봇에게 주는 기술적 안내일 뿐이고, 자료의 권리나 이용약관을 대신하지 않습니다.
그래서 **자료를 만든 주체가 회사 자신인 공식 홈페이지**로 범위를 좁혔습니다.

## 수집 결과 상태

| 상태 | 뜻 |
|---|---|
| 수집함 | robots.txt가 허용했고 페이지를 가져옴 |
| robots.txt가 수집을 막음 | 첫 페이지 경로가 막혀 있어 가져오지 않음 |
| robots.txt를 확인할 수 없어 건너뜀 | robots.txt 요청이 실패해 보수적으로 건너뜀 |
| 홈페이지에 접속하지 못함 | 주소가 없어졌거나 응답이 없음 |
| DART에 등록된 홈페이지 없음 | 수집 대상 주소가 없음 |

상태는 분석 결과마다 함께 저장되어 화면에 표시됩니다.
